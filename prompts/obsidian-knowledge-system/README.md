# DSH × Obsidian：让每一次探索，都能接着往下生长

> 精彩的对话值得留下。更值得留下的，是它的来由、你的理解，以及后来发现的联系和修正。

这是一份面向个人学习与研究的**知识探索与管理总提示词**。它规定 ChatGPT 与 DSH 如何协作：你继续在 ChatGPT 中追问与学习，再把讨论材料交给 DSH，经过筛选、独立核验和结构确认，整理进正在使用的 Obsidian 知识库。

## 它能帮你解决什么

| 常见困难 | 总提示词设计的处理方式 |
|---|---|
| 长对话里有精彩内容，过后很难找回 | 识别图片、例子、解释、公式、推导和代码，给出简洁候选目录，由用户选择 |
| 把回答存下来了，却忘记当时为何重要 | 保留必要上下文、触发问题、来源链接和原始精彩内容 |
| 当时觉得懂了，后来发现理解偏了 | 保留用户最初理解，再记录独立核验意见和后续纠错 |
| AI 原回答可能有错 | 根据知识类型重新推导、查证、模拟或测试，分别标记证据状态 |
| 同一主题不断讨论，笔记容易重复 | 把后续链接作为增量，更新受影响的笔记与整理进度 |
| 项目越来越多，知识互不相干 | 跨项目分析实质联系，在报告中提出有理由的关联建议 |
| 图片下载失败，任务容易搁置 | 在整理工作台集中登记缺失素材、目标笔记和插入位置，补齐后继续 |
| 老笔记出现过时、矛盾或失效链接 | 通过定期检查查证问题、追加纠错并维护文件与链接 |

## 从一次讨论到一篇可用笔记

总提示词给出的典型流程是：

~~~text
提供 ChatGPT 讨论材料与项目归属
→ 读取完整可得内容，识别新增部分
→ 你指定片段，或从候选目录中选择
→ 独立核验知识内容
→ 记录你的最初理解并检查
→ 提出笔记合并、拆分与排列方案
→ 你确认后写入 Obsidian
→ 补齐素材，更新索引与工作台
→ 后续增量维护、关联发现与健康检查
~~~

你已经明确指定要保存的内容，不重复询问是否保存；助手额外推荐的内容，仍由你决定。暂时说不清理解时，可以先保存并标记“待理解核验”，不会把复述正确答案作为保存门槛。

## 一篇笔记里保留什么

根据图片、例子、公式或推导的特点灵活组织，尽可能保留：

- 必要背景与完整的精选内容。
- 用户最初理解，尽量保留原话。
- 助手对理解的检查意见。
- 用户理解状态与知识内容状态。
- 来源 ChatGPT 链接及触发问题。
- 后续核验、争议与纠错的记录。

一篇笔记包含多个知识单元时，各单元分别保留状态，避免把某一处已核验误当作整篇全部可靠。

### 两个状态，分别回答两个问题

| 状态维度 | 回答的问题 | 示例 |
|---|---|---|
| 用户理解状态 | 你是否准确理解了这段内容？ | 待理解核验、未发现明显理解问题、存在理解偏差 |
| 知识内容状态 | 这段内容本身是否可靠？ | 尚未查证、未发现明显错误、待核实、已确认错误、已纠错 |

例如，你可能准确理解了一段本身有误的解释；也可能误解了一段正确解释。保留两个维度，可以让之后的复习与纠错更有针对性。

## 项目怎样管理

总提示词建议在**已有 Vault** 中维护以下角色的文件，具体目录按实际情况调整：

~~~text
现有 Obsidian Vault/
├── 知识库总规则.md
├── 项目总览.md
├── <项目目录>/
│   ├── 项目总体笔记.md
│   ├── 整理工作台.md
│   ├── 知识卡片/
│   └── 附件/
└── 知识库报告/
~~~

- **知识库总规则**：保存跨聊天共用的稳定约定，修改需先展示并获得同意。
- **项目总览**：记录项目目标、位置、链接及状态。
- **项目总体笔记**：保留跟随真实讨论成长的极简框架，在合适位置连接知识笔记。
- **整理工作台**：集中管理尚未完成的整理、结构确认和缺失素材。
- **知识库报告**：保存每次周报、月报，保留历史。

多项目可以并行。新项目由用户明确声明；项目结束由用户明确决定；重新开启沿用已有目录和历史。不同聊天通过本地项目文件恢复状态，不把单次对话记忆当作共享数据库。

## 每周探索与每月检查

这些是文档规定的运行目标，需要环境实际提供调度、读取、检索与文件写入能力。

| 工作 | 原文约定时间 | 重点 |
|---|---|---|
| 每周知识探索报告 | 每周日 09:30 | 首次全库了解，此后重点比较当周新增／修改内容与旧知识，发现关联、缺口、新问题和迁移机会 |
| 每月知识库健康检查 | 每月第一个周日 09:30 | 重新检查全库的准确性、时效性、矛盾、附件、双链、重复内容和结构问题 |

每月检查日同时生成当周周报。运行时应明确任务使用的时区和平台调度方式。

已确认错误按原文规则追加纠错，保留原始内容与最初理解；证据不足则标明争议和缺失证据。报告按影响程度组织，提供来源链接，减少对已经处理事项的重复提醒。

## 主动维护与用户决定怎样配合

总提示词区分了项目内维护、跨项目修改和删除等权限：

- 在用户确认的项目范围内，按约定持续整理与维护。
- 跨项目可以先读取分析，建立双链或修改文件前说明实质联系并征得同意。
- 删除任何笔记或附件前，列出路径、原因、损失与预期结果并取得明确同意。
- 修改全局规则前，展示具体改动与理由。
- 发现关联应说明共同原理、前置关系或应用价值，单纯关键词相同不足以建立关系。

这些规则用于实际启用这份工作流时；本仓库发布文档本身不会启动任何知识库操作。

## 如何开始使用

1. 打开[总提示词原文](DSH_Obsidian_知识探索与管理系统_总提示词.md)，完整交给准备执行的 DSH／助手。
2. 提供正在使用的 Obsidian Vault 的绝对路径，说明当前项目及允许处理的范围。
3. 提供 ChatGPT 分享链接，或可读取的对话导出／正文，以及关联图片或附件。
4. 可直接指定值得保存的片段，也可让助手先展示候选目录。
5. 按总提示词完成理解记录与结构确认，再在实际能力和授权范围内写入。
6. 如需周报和月报，单独确认运行环境能创建调度，并以实际创建结果核对是否启用。

## 运行条件与原文边界

| 能力 | 作用 |
|---|---|
| 本地文件读取与授权写入 | 访问现有 Vault、维护 Markdown 与附件 |
| 分享页或导出内容读取 | 分析完整可得对话，识别增量 |
| 图片读取与文件获取 | 保存并核验原图、图表及其他素材 |
| 可靠检索、推导或代码执行 | 根据知识类型独立核验 |
| 持续可用的定时任务能力 | 在指定时间生成报告 |

原文提到曾经成功的 ChatGPT 分享数据接口，这是历史经验，并未附带可独立安装的接口实现；可用性取决于当前平台、链接和访问条件。缺失素材可以按工作台流程补充，读取不完整时应明确报告范围。

这份文件是**总提示词原文**，没有 `SKILL.md` 格式的技能清单，也没有附带后台服务、Obsidian 插件或调度脚本。它定义助手如何工作，执行能力由运行环境提供。不会因为下载或上传而自动同步聊天、连接 Vault、创建周/月任务或发送通知。
