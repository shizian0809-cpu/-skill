# 名词解释 PDF 制作

> 从教材原页出发，把定义变成有出处、可双链、可检查的概念卡。

**输入 PDF，输出 Obsidian Markdown 概念卡与章节索引。** 适合把教材中的正式定义整理成可查询的知识入口，并保留回原书核查的线索。

## 会产出什么

| 产物 | 内容与用途 |
|---|---|
| 每个术语一张概念卡 | 教材定义原句、英文信息、来源定位，以及“为什么需要这个概念”的解释 |
| 每章一份索引 | 中文双链、英文、PDF 页／书页／段落，按原书小节组织 |
| 提及但未定义的附录 | 保留候选线索，同时与有正式定义的词区分 |
| 原页渲染图 | 作为复核来源，按原 Skill 的要求保留 |
| 可选学习进度记录 | 相对基线的内容变化、总进度条、分章表、最近改动与新增／删除卡片 |

## 工作方法为什么可靠

1. **先诊断 PDF**：判断扫描件、隐藏 OCR 或乱码文本层，校准 PDF 页码与书上页码。
2. **逐页渲染、视觉核对**：文本层可用于定位候选词，定义抄录以页面图像为依据。
3. **按定义句收录**：有明确界定的词进正表，仅被提及的词进附录。
4. **保留原句与教学解释的区别**：定义逐字照抄，解释另列；原书疑似印错应注明。
5. **先完成一章样例**：确认格式后再扩展，减少全书返工。
6. **脚本检查后回原文抽查**：结构一致性检查与原文准确性核对各自完成。

## 卡片的大致样子

以下为格式示意，实际定义应来自所提供教材。

~~~markdown
**术语  English** ｜PDF/书页/段 : 64/37/2

**书上的定义**：在这里逐字记录教材原句。

**为什么要有这个概念**：
从实际困难出发，用具体例子解释它帮助区分、计算或解决什么。
~~~

配套索引以 `[[01 术语]]` 等双链连接卡片。原始脚本遵循 Skill 中的编号、文件名和目录约定；采用其他命名规范时，需同步适配验证规则。

## 随附工具

### check.py：检查卡片与索引是否对得上

[查看脚本](scripts/check.py)。只使用 Python 标准库，主要检查：

- 索引双链与卡片文件是否对应，是否存在缺链、死链或重复双链。
- 每章编号是否从 01 连续递增。
- 索引与卡头记录的 **PDF 页码** 是否一致。
- 卡片行数是否在设定范围内。

该脚本比较的是 PDF 页码，并不自动核对全部书页、段落或定义原文。它不能替代视觉复核。

~~~powershell
python -X utf8 "<技能目录>/scripts/check.py" --root "<项目根>" --chapters 16
~~~

章节数和路径替换为自己的实际值。默认索引文件为 `索引/01名词解释.md`，卡片位于 `零散的概念/01 第X章/` 一类目录；可通过 `--index-dir`、`--cards-dir`、`--index-name` 等参数指定相应配置，章文件夹仍需符合脚本匹配规则。

### progress.py：记录卡片内容相对基线的变化

[查看脚本](scripts/progress.py)。只使用 Python 标准库，以 SHA-256 内容指纹判断卡片是否变化。内容改回原样后不计入已改；新增和删除单独列出。

~~~powershell
# 所有卡片定稿后，建立一次基线
python -X utf8 "<技能目录>/scripts/progress.py" --root "<项目根>" --init

# 此后统计并生成报告
python -X utf8 "<技能目录>/scripts/progress.py" --root "<项目根>" --title "教材知识点学习进度"
~~~

脚本会在项目 `_学习进度/` 下写入基线、Markdown 报告和历史记录。重新 `--init` 会把当前内容设为新的起点。AI 批量改写、格式调整也会导致内容指纹变化，所以“已改卡片比例”应视为整理活动指标，不能直接等同于掌握率。

## 开始使用

~~~text
$mingci-jieshi-pdf 整理这本教材的第一章。
PDF 路径：<绝对路径>
项目根目录：<Obsidian 内的目标位置>
先校准页码，给出一章卡片与索引成品，确认后再扩展。
~~~

初次需确定源 PDF、目标位置、章节范围、命名与英文列处理。完整规则位于 [SKILL.md](SKILL.md)，技能标识为 `mingci-jieshi-pdf`，安装方法见[仓库首页](../README.md#安装与调用)。

## 运行条件与案例档案

PDF 阅读和渲染部分需要可用的 Python／PyMuPDF 及图像阅读能力。原始说明使用 `D:\tools\Miniconda\python.exe`、`pdf-toolkit` 和 DeepSeek Harness 工具名；应替换为当前机器已具备的等效环境。仅使用两个检查／进度脚本不需要 PyMuPDF。

[《试验统计方法》参考档案](references/试验统计方法.md)保留了原案例的章节范围、页码偏移、408 张卡片的历史统计和项目约定。这些是案例参数，不能直接套给另一本书。教材 PDF、实际概念卡与页面渲染图未随本仓库发布。

原文还提供定时汇报与消息推送的接入思路，需要相应任务和消息工具；仓库中的脚本本身不会自动配置定时服务。
