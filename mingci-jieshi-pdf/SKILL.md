# 名词解释 PDF 制作

一次把一本书的「定义名词」变成 **Obsidian 概念卡 + 章节索引表**。

产出两张网：

- **索引**：每章一张 Markdown 表，三列 = 中文双链 / 英文 / `PDF页/书页/段`。
- **卡片**：每个名词一个 `.md`，三段式，第二段是书上原句逐字照抄。

---

## 铁律（违反即返工，不可协商）

1. **必须逐页渲染成图 + `read_image` 视觉识读。禁止用 PDF 文本层抄定义。**
   扫描件的文本层是 OCR 结果，错字率常在 15%–30%（本次实测：`试验方案` 被识别成 `试验大案`，整行成乱码）。文本层只允许用来**定位候选词**，绝不能作为抄写来源。
2. **定义逐字照抄**。不改写、不概括、不补全、不换成自己的话。书上写错字就照抄，另加一句脚注说明。
3. **正表只收有定义句的**。只有举例、用途、分类说明而没有「X 是…… / 称为 X」这类句子的，一律进文末「提及但未给定义」附录，不进正表。
4. **收工前必须回原文抽查 2–3 条**，把书页原句与卡片对照，如实报告（对不上就说对不上）。
5. **渲染出的图片保留，不要删**。那是复核底片。
6. **页码三口径**：`PDF 页码 / 书上页码 / 该书页内第几段`。三个都写，少一个就查不回去。

## 第 1 步：诊断 PDF（别跳，15 分钟省几小时）

优先调用 `pdf-toolkit` 技能，用它的解释器 `D:\tools\Miniconda\python.exe`。**不要 pip install**。

### 1.1 判断这是哪一种 PDF

```powershell
$env:PYTHONIOENCODING='utf-8'
& 'D:\tools\Miniconda\python.exe' -X utf8 -c @"
import pymupdf
doc = pymupdf.open(r'<PDF>')
print('pages', len(doc), 'toc', len(doc.get_toc()))
for i in (0, 1, 50, 100):
    p = doc[i]
    print(i+1, 'chars', len(p.get_text()), 'imgs', len(p.get_images()))
"@
```

- 每页 `chars = 0` → 纯扫描件，无文本层，只能靠读图。
- 每页 `chars > 0` 但复制出来的字是乱码 → **缺 ToUnicode**，见 1.2。
- 每页 `chars > 0` 且可读 → 文字型 PDF，仍要先抽查 2 页确认没有错字（转曲、OCR 冒充都可能）。

### 1.2 缺 ToUnicode 时怎么把字读出来（只用于定位）

字体是 `SimSun / Type0 / GBK-EUC-H` 且无 ToUnicode 时，`get_text()` 会返回乱码，但内容流里的十六进制串其实是 GBK 字节：

```python
import re
cont = doc.xref_stream(doc[29].get_contents()[0])
for blk in re.finditer(rb'BT(.*?)ET', cont, re.S):
    for sm in re.finditer(rb'\[(.*?)\]\s*TJ', blk.group(1), re.S):
        for part in re.finditer(rb'<([0-9a-fA-F]+)>', sm.group(1)):
            print(bytes.fromhex(part.group(1).decode()).decode('gbk', 'replace'))
```

顺带检查是否**隐藏文本层**：内容里有 `3 Tr`（不可见渲染模式）就说明这层 OCR 是给搜索用的，肉眼看不到，也就更不能信。

解出来的字**只用来找候选词在哪一页**，抄写仍然回到图上看。

### 1.3 校准书页偏移

渲染一页带页码的正文页，看页脚数字：

```python
doc[29].get_pixmap(dpi=160).save('_诊断/p030.png')
```

书页 3 对应 PDF 30 → 偏移 `−27`。**每一章开头都要再验一次**，书里如有插页、彩色页，偏移会变。

### 1.4 收集候选词（不是证据）

把用户给的清单 + 全文搜出来的词（双字到六字的中文词）列成候选池：

```python
for kw in ['试验单元', '试验误差', '准确度', '精确度']:
    hits = [i+1 for i in range(len(doc)) if kw in ''.join(extract(i))]
    print(kw, hits[:20])
```

候选池只回答「去第几页找」，不回答「书上怎么定义」。

## 第 2 步：逐页渲染、逐页读图

```python
import pymupdf, os
doc = pymupdf.open(PDF)
os.makedirs('_渲染第N章', exist_ok=True)
for pg in range(a, b + 1):
    doc[pg - 1].get_pixmap(dpi=170).save(f'_渲染第N章/pdf{pg:03d}.png')
```

- **dpi 170** 是正文的性价比点；表格、公式、小号注释用 280–400 dpi **局部裁切**放大复核。
- 一次 `read_image` 3–5 页，读完就把「定义句原文 + 三口径页码」记下来，**别攒到最后**。
- 读图时的四个坑：
  - 跨页断句（句号在下一页开头）——两页都要读；
  - 表格里的定义（如「矩分为原点矩和中心矩」）；
  - 公式定义（`cov = ...` 后面跟一句「称为协方差」）；
  - 目录页、习题页不算正文，但**章末「名词解释」习题是判定重点的线索**。

## 第 3 步：判定「这算不算定义」

收：

- `X 是指……` / `X 是……的……`
- `……称为 X（English）` / `……称为 X，简称 X`
- `所谓 X，即……`
- 定义句里常带英文括注，那是英文列的第一来源

不收（进附录）：

- 只在标题或小标题出现，正文没解释；
- 只讲用途（「制作标准曲线的目的在于……」）；
- 只给分类或公式（「矩分为原点矩和中心矩两种」但没解释什么是矩）；
- 只有同义名（「也称为 2 重格子设计」）。

判断有疑问时，**宁多勿漏**地进附录，但正表宁少勿滥——正表的每一条都要能指着书上原句说话。

同时记下**同义/近义分流**：同一概念在不同章用了不同词（如第一章「准确性」、第二章「准确度」），各收一条，并在卡片里注明对应关系。

## 第 4 步：写卡片（三段式，用户只要这三段）

路径：`<项目根>\零散的概念\NN 第X章\序号 术语.md`

```markdown
---
tags:
  - 统计
  - 概念卡
---

**术语  english** ｜PDF/书页/段  :  64/37/2

**书上的定义**：<从这里开始逐字照抄，一个字都不许改>

**为什么要有这个概念**：
<3–8 段。先讲「没有它会怎样」，再讲它解决了什么，可以放小表、例子、算式。
口语化，但不要编造书里没有的结论。>
```

硬约束：

- **文件名 = 卡头里 `**术语**` 那串 = 索引里的双链名**，三处一字不差（含中间那个空格、含序号）。差一个字 Obsidian 就是死链。
- 行数 30–80 行为宜（本次 408 张卡实测区间 30–48 行）。
- 定义原句里若有明显印错（如「随机变数是……的任意数值」），照抄并在后面用一句「（原文如此）」标注，不要把错字改成对的。

## 第 6 步：并行分工（章数 ≥ 3 时必须用）

一个章 = 一个子代理 = 一个独立会话。**成员直接写文件，不回传全文**，只回报结论。

### 每个成员必须拿到的五项（缺一项就会跑偏）

1. **写入范围**：只许写 `索引\NN名词解释.md` 与 `零散的概念\NN 第X章\`，明确「不得改其他章、其他索引」。
2. **固定骨架**：第 4 步的卡片模板、第 5 步的索引模板，原样贴给它。
3. **命名规则**：`NN 第X章`、`序号 术语.md`、双链名 = 文件名。

5. **回报格式**：条数、页码范围、自检结果、不收录但值得一提的 3–5 项。

## 第 8 步（可选）：学习进度追踪

卡片交出去之后，用户会一边学一边改写它们。给一份「408 张里改了多少张」的进度，比自己翻着数有用。

**判定口径只能是内容指纹**（sha256），不能用修改时间：Obsidian 打开、同步、复制粘贴都会刷新 mtime，靠不住。
卡片全部定稿后跑一次 `--init` 建基线，此后每次比对——内容变了才算改过（改一个字也测得出来），改完又改回原样不算。

**脚本**：`<skill-directory>\scripts\progress.py`

```powershell
# 建基线（一次性；从此算 0%）
& 'D:\tools\Miniconda\python.exe' -X utf8 "<skill-directory>\scripts\progress.py" --root "<项目根>" --init
# 日常统计（刷新 进度报告.md 并打印）
& 'D:\tools\Miniconda\python.exe' -X utf8 "<skill-directory>\scripts\progress.py" --root "<项目根>" --title "《书名》知识点学习进度"
```

产物落在 `<项目根>\_学习进度\`：`baseline.json`（指纹基线）、`进度报告.md`（总进度条 + 分章表 + 最近改动）、`history.json`（用来算「较上次 +N 张」）。

**定时汇报**：任务板一张卡 + cron，到点启一个短会话跑脚本、刷报告、发消息。

```text
task_board_create：标题「《书名》知识点学习进度」
prompt：跑 progress.py → 刷新报告 → send_wechat 发「总进度 X/N（xx%），较上次 +N 张」
        + 已改数>0 的章节（最多 6 行）→ 一句话回报
task_board_schedule：mode=cron, cron="0 21 * * *", timeZone="Asia/Shanghai"
```

**三个坑**：

- `--init` 会把当时状态当 0%。批量重写、或由 AI 统一改格式之后，必须重建基线，否则进度虚高。
- 项目里若要放一份 `progress.py`，就写成**薄壳**（只传 `--root` 和 `--title`，主体 `runpy.run_path` 技能脚本），保证逻辑只有一份，不会分叉。
- 报告里的章节名取自卡片目录名（`NN 第X章`），所以目录命名要一开始就定死。

## 已知坑（都是踩过的）

- **Windows 控制台是 UTF-8，Python 默认 GBK**：不设 `PYTHONIOENCODING=utf-8` 并加 `-X utf8`，中文输出会变成 `����`。
- **`python -c` 里塞长中文字符串会崩**（`python.exe: can't open file`）：改用 `@""@` heredoc 或写临时 `.py` 文件再执行。
- **`Get-Content` 读 UTF-8 文件会显示乱码**：那只是显示问题，文件本身没问题，别以为写坏了。
- **页码口径混用**：目录上的页码、书页、PDF 页是三回事，混一次全表都要返工。
- **文件名与双链名不一致**：中文全角/半角空格、`+` 号、序号位数不同都会造成死链，验收脚本会抓出来。
- **切分卡片时用正则要认准卡头行**：`^\*\*(.+?)\*\*\s+｜PDF/书页/段` 比按 `---` 分割可靠。
- **渲染图别删**：用户要留着复核；旧图占几百 MB 是正常的。
